# StoryForge
> **Write together, branch by branch.**

## Problem
Indie writers often write interactive narratives in isolation, lacking a lightweight tool to manage complex branching structures and collaborate in real time. Existing writing platforms either focus on linear prose or require heavy technical setup for version control and collaboration. This gap forces authors to juggle multiple tools, slowing creativity and increasing the risk of lost work.

## Target Users
- Indie authors who write interactive fiction  
- Small publishing teams creating branching stories or games  
- Game writers needing narrative design tools  
- Interactive fiction enthusiasts looking to co‑create  
- Educators using narrative projects in classrooms  

## Key Features
- Real‑time collaborative editing with operational transformation (OT)  
- Visual branching canvas for mapping story nodes and choices  
- AI‑powered suggestion engine for plot twists, dialogue, and character arcs  
- Export to Twine, Ink, and interactive web formats (HTML/JavaScript)  
- Built‑in version control with Git‑style commit history  
- Analytics dashboard: reader path heatmaps and engagement metrics  
- Publish‑ready integrations (Amazon Kindle, itch.io, Gumroad)  

## Tech Stack
- **Frontend**: React + TypeScript, Zustand for state, TailwindCSS, D3.js for branching UI  
- **Backend**: NestJS (Node.js, TypeScript) with WebSocket (Socket.IO) for real‑time sync  
- **Database**: PostgreSQL (relational), Redis (caching), Neo4j (graph of story branches)  
- **Infra/DevOps**: Docker, Kubernetes (Helm), GitHub Actions CI/CD, Terraform for cloud provisioning, AWS (EKS, RDS, S3)  
- **AI/ML**: OpenAI GPT‑4 via REST API, HuggingFace Inference API for embeddings, custom fine‑tuned Llama model for local inference  

## Architecture
StoryForge follows a microservice architecture with a central **Collaboration Service** handling real‑time OT and change streams, a **Content Service** managing story nodes and branching logic, and an **AI Service** providing language model inference. The frontend connects via GraphQL over HTTP and WebSocket for live updates. Data is stored in PostgreSQL for structured metadata, Redis for session state, and Neo4j for efficient traversal of branching graphs. The system is containerized, orchestrated by Kubernetes, and deployed on AWS EKS with CI/CD pipelines automating tests and releases.

## Roadmap
- **v1** – Core real‑time collaboration, branching canvas, basic AI suggestions, version control, export to Twine  
- **v2** – Advanced AI editing (character voice, consistency checks), analytics dashboard, publishing integrations, mobile responsive UI  
- **v3** – Plugin marketplace, multi‑language support, custom LLM fine‑tuning, enterprise‑grade security, offline desktop app via Electron
