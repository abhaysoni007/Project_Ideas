# PulseGrid  
> “Lint your email, lift your accessibility—no AI, just pure rule‑based precision.”

## Problem  
Many marketing teams ship HTML emails with hidden accessibility barriers—missing alt text, improper color contrast, and inaccessible table structures—that slip through manual review. Existing AI‑driven linters are costly, opaque, and often produce noisy suggestions that distract developers.

## Target Users  
- Email marketing agencies that deliver bulk HTML campaigns  
- Front‑end developers crafting transactional or promotional email templates  
- QA engineers responsible for cross‑client email rendering compliance  
- Accessibility specialists needing quick, deterministic linting results  
- CI/CD pipelines in DevOps teams that enforce email standards  

## Key Features  
- **Rule‑based accessibility checks** for WCAG 2.1 AA in email HTML  
- **Custom rule configuration** via a simple JSON schema  
- **Integrated VS Code extension** for instant lint feedback  
- **CLI tool** that runs in CI environments and outputs SARIF reports  
- **Cross‑client rendering simulation** to flag layout issues in Outlook, Gmail, and mobile clients  
- **Auto‑fix suggestions** for trivial issues (e.g., missing alt attributes)  
- **Extensible plugin system** for adding organization‑specific rules  

## Tech Stack  
- **Frontend**  
  - React 18 + Vite (UI for the web dashboard)  
  - Tailwind CSS (utility‑first styling)  
- **Backend**  
  - Node.js 20 (TypeScript)  
  - Express.js (REST API)  
  - htmlparser2 & posthtml (HTML parsing & manipulation)  
- **Database**  
  - SQLite (embedded) for storing rule sets and linting history  
- **Infra/DevOps**  
  - Docker (containerization)  
  - GitHub Actions (CI/CD, automated release)  
  - AWS S3 (static asset hosting)  
  - Cloudflare Pages (frontend hosting)  
- **AI/ML**  
  - None (pure rule‑based engine)

## Architecture  
PulseGrid follows a modular micro‑service architecture: the **CLI** and **VS Code extension** communicate with the **Backend API** over HTTPS to run linting jobs. The API orchestrates the rule engine, leveraging `htmlparser2` to parse email HTML, applies rule definitions stored in SQLite, and returns structured results. The **Web Dashboard** consumes the API to display lint history, rule configuration, and cross‑client rendering previews. All services are containerized and deployed via GitHub Actions to AWS and Cloudflare, ensuring rapid, reproducible releases.

## Roadmap  
- **v1** – Core rule engine, CLI, VS Code extension, SQLite persistence, CI integration, basic web UI.  
- **v2** – Advanced rendering simulator for Outlook/Thunderbird, plugin architecture, SARIF support, Docker image publishing.  
- **v3** – Webhook API for third‑party integrations, collaborative rule editing, AI‑assisted rule suggestions (optional), performance optimizations for large email payloads.
